1. Create Order (US-2.1: 结构化订单创建)

sequenceDiagram
    actor CSR as 👤 Customer Service Staff
    participant GW as 🌐 API Gateway
(FastAPI)
    participant OS as 📦 Order Service
(gRPC :50051)
    participant DB as 🗄️ MySQL
(hsp_order.orders)

    CSR->>GW: POST /api/orders/v1/orders
{customer_name, phone, address, type, time, duration}
    GW->>GW: JWT Auth + RBAC check
(role=CUSTOMER_SERVICE/OWNER)
    GW->>OS: gRPC CreateOrder
(CreateOrderRequest)

    OS->>OS: Validate required fields
(customer_name, phone, service_address)

    alt Missing required fields
        OS-->>GW: INVALID_ARGUMENT error
        GW-->>CSR: 400 Bad Request
    else Validation OK
        OS->>OS: Generate UUID order_id
        OS->>OS: Set status = CREATED
        OS->>OS: Set created_at / updated_at
        OS->>DB: INSERT INTO orders VALUES (...)
        DB-->>OS: Row inserted
        OS-->>GW: CreateOrderResponse {order}
        GW-->>CSR: 201 Created
{order_id, status: "CREATED", ...}
    end

2. Order Status Transition (US-2.2: 状态流转)

sequenceDiagram
    actor Staff as 👤 Staff / System
    participant GW as 🌐 API Gateway
    participant OS as 📦 Order Service
(gRPC :50051)
    participant DB as 🗄️ MySQL

    Staff->>GW: PATCH /api/orders/v1/orders/{id}/status
{target_status, assigned_worker_id}
    GW->>GW: JWT Auth + RBAC check
    GW->>OS: gRPC UpdateOrderStatus
(order_id, target_status, assigned_worker_id)

    OS->>DB: SELECT * FROM orders WHERE order_id = ?
    DB-->>OS: Order record (current_status=CREATED)

    alt Order not found
        OS-->>GW: NOT_FOUND
        GW-->>Staff: 404 Not Found
    end

    OS->>OS: Validate transition:
CREATED -> PENDING ✓

    alt Illegal transition
        OS-->>GW: FAILED_PRECONDITION
"cannot transition from X to Y"
        GW-->>Staff: 409 Conflict
    else Valid transition
        OS->>OS: Update status, assigned_worker_id
        OS->>OS: Set status_updated_at = now()
        OS->>DB: UPDATE orders SET status=?, ... WHERE order_id=?
        DB-->>OS: Row updated
        OS-->>GW: UpdateOrderStatusResponse {order}
        GW-->>Staff: 200 OK
{status: "PENDING", ...}
    end

3. Complete Order Lifecycle State Flow

sequenceDiagram
    participant CSR as Customer Service
    participant SYS as Order Service
    participant WKR as Worker
    participant PAY as Payment Service

    Note over CSR,PAY: Full Order Lifecycle (CREATED → PAID)

    CSR->>SYS: 1. CreateOrder → CREATED
    SYS-->>CSR: order_id=ord-001, status=CREATED

    CSR->>SYS: 2. UpdateOrderStatus → PENDING
    SYS-->>CSR: status=PENDING (ready for dispatch)

    CSR->>SYS: 3. Assign worker: UpdateOrderStatus → ACCEPT
    SYS-->>CSR: status=ACCEPT, worker_id=w-001

    WKR->>SYS: 4. Service complete: UpdateOrderStatus → COMPLETE
    SYS-->>WKR: status=COMPLETE

    Note over PAY: Payment callback received

    CSR->>SYS: 5. Payment confirmed: UpdateOrderStatus → PAID
    SYS-->>CSR: status=PAID (order closed)
State Machine Validation Rules (order-service):
✅ CREATED → PENDING  |  ✅ PENDING → ACCEPT  |  ✅ ACCEPT → COMPLETE  |  ✅ COMPLETE → PAID
❌ CREATED → PAID (非法)  |  ❌ CREATED → COMPLETE (非法)  |  ❌ PAID → * (终态，不可逆)
